# 首次业务开通

本参考用于当前 `read_context` 明确返回 `accountStatus=not_provisioned`。执行任何持久写入前，完整读取[账号写入与未知恢复](account-operations.md)。下列原文所称“下方明确选择与原对话绑定”是入口的同名部分；本人明确选择后，必须先读完整[选择核验指引](selection-binding.md)，再执行核验。

### 首次业务开通

当 `read_context` 返回 `accountStatus=not_provisioned` 时，先明确说明：登录账号已经验证，但 AI书桌业务账号尚未初始化。不要把它说成“空家庭”，也不要因为这个状态自动创建家庭、学习者或选择目标。向用户询问并等待其明确确认：家庭显示名和首位学习者显示名；只收集这两个显示名，不据此推断年龄、能力或其他儿童资料。

用户明确确认开通后，按以下顺序执行：

1. 为创建家庭预先生成一个新的 UUID `operationId`，调用 `aidesk_create_family`。成功后记录实际返回的 `familyId`；返回 `outcome_unknown`、超时或中断时，必须用同一编号查询 `aidesk_operation_status`，不能换编号重试。
2. 仅在家庭创建结果已确认且用户已确认首位学习者显示名时，用另一个新的 UUID 调用 `aidesk_create_learner`，传入刚刚返回的 `familyId`。学习者创建失败或结果未知时，说明家庭已创建但首位学习者尚未确认，不自动重复创建或修改家庭。
3. 两项操作完成后重新调用 `aidesk_read_context`，核对账号状态、家庭 ID、学习者 ID 和管理权；读取失败时只报告已确认的历史操作，不能把写入回执当作当前状态。
4. 创建家庭或学习者不会自动绑定或选择学习者。后续必须由用户明确指定家庭和学习者，再按下方“明确选择与原对话绑定”流程继续。

如果账号已经有家庭，不能再次走首次开通；先按当前结果让用户明确要进入哪个家庭。家庭创建和学习者创建均是明确的持久写入，缺少名称、确认或当前身份时保持只读并说明停点。
