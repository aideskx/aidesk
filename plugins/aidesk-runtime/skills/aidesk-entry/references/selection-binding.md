# 选择核验、绑定与失效处理

入口已要求明确选择；在选择、切换、重新确认及既有绑定失效、取消或结束时，完整读完本参考再执行对应分支。下列原文中的“下方规则”指[账号写入、冻结功能与恢复](account-operations.md)中的原号对账规则；出现旧写入未知时先完整读取它，不把逻辑撤销写成持久操作已撤回。首次进入教学或开始新任务且选择核验成功后，返回入口按原完整教学加载规则继续。同一教学范围内的有效重核沿原执行接续，不因此重新检查 Plugin 更新或重新加载已在当前上下文可用的完整正文；仍执行原教学参考要求的权限、版本及来源核验。未选择或未核验成功时不进入教学。

每次选择、切换或重新确认，按以下顺序在原对话执行：

1. 先逻辑撤销旧绑定及旧 `attemptId`，停止把旧主体或学习者的资料用于后续操作；确认当前为未绑定，再开始本次尝试。失败、取消或结果不可靠时保持未绑定，不回退到旧绑定。
2. 用本次完整成功且仍有效的 `aidesk_entry_context.account` 或原 `aidesk_account_status` 回执确认当前 `subject`；前者已完成当前核验时不重复调用后者，失效时仍须重新核验。将用户明确选择且经当前获准列表映射的 `familyId`、`learnerId` 与新 UUID `attemptId` 作为原对话当前待确认目标。`attemptId` 仅作结果相关性标记，不是凭据、授权来源或写入 `operationId`，不查询操作回执，不跨对话复用。
3. 调用 `aidesk_check_selection`，只传 `familyId`、`learnerId`、`attemptId`。它重新读取当前权限；不传旧列表的 `expectedVersion`，也不根据旧版本、角色或摘要自判准入。
4. 只采纳成功且 `status=checked`、`subject`、家庭 ID、学习者 ID、`attemptId` 全部与当前待确认项一致的结果，并确认当前尚未到达 `recheckAt`。切换、结束、取消或失效后到达的旧结果一律拒用；若当前时间或对应关系无法可靠确认，保持未绑定并重新检查，不能据返回顺序选择赢家。
5. 将这次结果作为原对话的逻辑绑定，简明复述实际返回的学习者显示名和必要的家庭区分信息。内部 ID、检查时刻、权益到期、`recheckAt` 与版本用于当前核验及必要追溯，不要求每次向用户逐项展示，也不将其当作后续授权。到期、需要重新确认或歧义影响当前使用时，解释具体影响及下一步；涉及时间时使用用户时区。

`recheckAt` 是本次认证、账号内存会话和账号权益期限的保守上限，不是保证期间不会撤权的授权租约。到达该时间、已知账号或权益变化、认证失败、读取失败或绑定不可靠时，先撤销旧绑定及待确认尝试；只有重新检查成功才能继续使用目标。原对话中用户明确要求继续或恢复，也重新检查原目标，不凭旧结果续用；无法确定原目标时让用户明确选择。按这些边界查权，不要求普通每轮远端读取。

用户要求结束时立即撤销原对话绑定及待确认尝试，说明已结束本次选择；不再调用选择检查，也不将结束等同退出账号。下次选择必须开始新尝试。服务端逐次检查身份、当前账号家庭、目标学习者与共享权益，并在交付前检查已知到期；本结果不能授予未实现工具权限。

撤销旧绑定时，同时停止把它对应的新回合、语音、画面与可视化、工具结果、当前观察或主动新写入用于后续操作。已发出但尚未返回的旧读取或观察，返回后仍属于旧绑定；不能因为它在新选择之后到达，就把它归给新学习者。无法可靠确认所属绑定的结果不采用；用户再次粘贴旧内容也不会自动取得新学习者的权限。切换、结束、取消、权限失效或绑定不可靠后，先前绑定的内容和迟到结果不得进入新学习者的上下文。

逻辑撤销不等于已发出的持久操作被撤回或数据被删除。旧写入结果未知时，只能按下方规则沿原 `operationId` 对账；不得改成新学习者 ID 或新编号重发。历史回执只说明原操作结果，不能恢复旧绑定或作为新学习者的当前状态。

同账号切换后的迟到结果拒用是本 Skill 的逻辑约定；当前接入没有执行这些规则的宿主硬过滤消费者。不能声称强制跨学习者隔离、即时撤权推送、清除宿主历史或已终止宿主中的其他工具，也不能保证旧内容已从模型上下文物理移除。Skill 静态检查不能替代新对话真实测试；实际观察到旧内容被误用时，停止依赖该绑定并如实报告失败，不能以指令存在判为通过。
